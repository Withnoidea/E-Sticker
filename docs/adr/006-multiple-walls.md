# 006：多分类墙与汇总首页

状态：用户确认；v0.3.0 实现

## 产品规则

1. 用户可自行创建、命名和删除分类墙，例如工作、学习、剪辑项目。每篇文章仅归属一面分类墙，不复制正文。
2. 首页兼作默认归属的创建入口，同时汇总所有未归档、未删除的文章。默认归属不显示为单独的分类墙；列表可筛选「未分类 · 仅首页」。
3. 首页主要用于观赏，允许自然错落、轻微倾斜和相互遮挡；用户可正常拖动。新增分类文章只增量加入，不自动打乱旧布局。
4. 分类墙保护用户的手工布局。首页位置和层级与分类墙独立，拖动一边不影响另一边。查看、搜索、排序和重新分类不改变首页位置。
5. 排序只作用于文章列表。列表支持全文、分类和标签筛选，能直接打开被遮住的文章，不要求先定位到墙面。
6. 删除分类墙会把全部所属文章（包括归档文章）移入回收站，从首页和正常列表移除；先提示墙名和受影响篇数。默认首页不能删除。
7. 恢复文章统一回首页默认归属，并解除归档，不重建旧墙。保留原首页位置。用户随后可以手动移入其他分类墙，或从分类墙移回默认归属。

## 数据与迁移

- `wall.json` v3 保存分类墙元数据 `walls`，每篇文章使用唯一 `wall_id` 指明归属；`0` 是隐含默认归属。
- 原 `at` 和文章数组顺序保留为首页位置及层级；`wall_at` / `wall_order` 保存当前分类墙的独立布局；`home_tilt` 保存首页倾角。
- 文章只有一份短句、Markdown、标签和生命周期状态。墙面、列表与详情引用同一个 ID。
- 读取 v1/v2 时保留原文章顺序和坐标，全部归默认，旧文章不自动倾斜。首次升级保存前以独占创建方式备份旧文件，不覆盖既有备份；备份失败则不升级原文件。
- 所有 UI 变更先作用于模型副本，原子保存成功后才切换内存状态。保存失败时保留原文章和界面草稿。
- 拒绝重复编号、重复墙名、非法墙编号及指向不存在分类墙的文章，避免无声丢失内容。旧版程序不支持 v3。

## 验收

- 首页新建 → 默认归属；分类墙新建 → 当前分类且首页只增加一份展示。
- 分别拖动首页、分类墙，验证另一边位置与层级不变；关闭重启后布局保持。
- 遮住一篇文章后，仍可从全文搜索和分类列表打开；列表排序不写墙面数据。
- 删除分类墙 → 包括归档内容在内的文章进回收站 → 恢复回默认首页 → 手动重新分类；文章 ID、正文、标签和首页位置保留。
- 取消操作、重名、写盘失败、旧数据迁移、最小窗口及实际解压发布包均需回归。
